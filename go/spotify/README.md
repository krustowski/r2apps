# Spotify Go prototype for Memento

`spotify.elf` is a separate **Go process** hosted in Memento, using the same
shared-user-heap arrangement as `sh.elf` and theM. The Memento adapter draws
snapshots and forwards mouse/keyboard commands. Go owns playlists, Spotify API
requests, PCM playback, goroutines, channels, file access and the model.

The experimental streaming engine runs inside rou2exOS: Spotify AP login and
Shannon transport, audio-key requests, bounded HTTPS range downloads, AES-CTR
decryption, and integer Ogg Vorbis decoding to HD Audio. Go owns the protocol
and buffering; Xiph's Tremor decoder is linked through Cgo. No host playback
backend or remote-device playback command is used. Premium is required.
Local WAV/Vorbis files and generated tones remain available for offline tests.

A live Premium account test verified native protocol authentication, audio-key
retrieval, encrypted downloads and decoding to PCM on the development machine.
Complete streaming through the r2 network and audio drivers still needs testing
on the target machine.

## Build and run

From `go/spotify`:

```sh
make build                   # builds portable BearSSL, Tremor, then spotify.elf
make test                    # host tests of API, playback protocol, decoder and host ABI
```

The build needs the existing `tinygo-r2:0.38.0` Docker image, GCC, ar, and the
BearSSL sources under `cpp/third_party/bearssl`. Go calls the portable C TLS
engine through Cgo; TCP, scheduling, application state and audio remain Go.
The reusable adapter lives in `go/r2tls`. The native build defaults to `OPT=1`; this can be overridden when building.

Build Memento with `make -C ../../cpp/memento-hello build`, then copy
`spotify.elf` into the boot medium's `bin` directory beside `memento.elf`.
`r2_main`'s ISO build includes both files. Boot the rebuilt ISO and open the
**Spotify** desktop icon. The no-account default includes two ten-second tone
tracks, generated by Go, so the window and local audio can be exercised first.
An HD Audio controller is needed for playback, for example QEMU's
`-device intel-hda -device hda-duplex`, with host audio configured normally.

## Spotify account setup

Register a Spotify developer app with this exact redirect URI:

```
http://127.0.0.1:8765/callback
```

On your development machine, provision credentials once:

```sh
python3 tools/login.py --client-id YOUR_CLIENT_ID --output SPOTIFY.CFG
```

This uses Authorization Code with PKCE and does not need a client secret.
The helper opens a browser, validates OAuth state, writes the refresh token
with mode 0600, and exits. It is only for sign-in; r2 refreshes access tokens
and makes API requests itself at runtime.

Copy `SPOTIFY.CFG` to the FAT root (`/mnt/fat/SPOTIFY.CFG`), or put its JSON in
`r2_main/iso/opt/spotify/config.josn` to ship it on the boot medium. The read
order is FAT, `/mnt/tar/opt/spotify/config.josn`, then `config.json` in the same
directory, followed by the equivalent ISO paths. Both spellings are supported.
Keep credential files private; don't commit them. The client persists rotated
refresh tokens to FAT when Spotify returns a replacement. It reports a write
failure rather than silently losing the replacement.

Press **Refresh / R** to load account playlists. Arrow keys only highlight playlists; press Enter to load the highlighted
playlist. Loading then focuses the song list. Clicking a playlist loads it directly. Playlists and songs are fetched ten at a time, with
page buttons above each list. Spotify's development-mode account/allowlist
restrictions and playlist permissions still apply.

### Playback pairing

Playlist credentials and playback credentials are separate. Keep your existing
Web API config and login helper. Select an account song and press Play: the
status line displays **spotify.com/pair** and a code. Authorize that code with
your Premium account from a browser. The r2 client polls the authorization
endpoint itself, then starts the playback session. Stop cancels pairing.

The client saves the renewable playback token and device ID to
`/mnt/tmp/SPOTIFY.KEY`, then reuses them after closing, reopening or a crash.
This RAM-disk cache lasts until reboot. `/mnt/fat/SPOTIFY.CFG` also receives
`streaming_refresh_token` when it supplied the account config, allowing reuse
across reboots. An ISO-only setup uses the RAM cache without attempting a floppy
write on every playback sign-in. The
config token is used when there is no valid RAM-disk key.
A save failure is reported and does not prevent playback in the current session.
Do not reuse the developer application's `refresh_token` in this field.

HTTPS requires Memento's `opt/memento/cacerts.bin` and a valid RTC. The client
tries RDSEED, then RDRAND. If hardware randomness is absent or exhausts retries,
it uses Memento's browser-style fallback: a 512-byte seed containing RTC/tick
values, a stack address, and timestamp-counter jitter across syscalls and short
sleeps. BearSSL mixes the seed through its HMAC-DRBG. This allows older CPUs
such as the i3-550 to attempt HTTPS without a new kernel syscall.

The fallback's entropy quality is **unverified**; a working TLS handshake does
not establish secure randomness. A tested OS entropy service remains the
long-term solution. Certificate and hostname verification remain enabled.
The r2 network stack must have a configured DNS server that accepts TCP queries.
The client uses DNS over TCP so it can coexist with the normal Ethernet
driver, which owns UDP packets. See `../r2net/README.md` for configuration.

## Local audio and controls

For a Spotify track with a local audio file, add its Spotify ID to the config:

```json
"local_files": {
  "SPOTIFY_TRACK_ID": "/mnt/tar/music/song.wav"
}
```

Local `.ogg` files use the same integer Vorbis decoder as Spotify streaming.
The WAV must be uncompressed signed PCM16 little-endian stereo at one of r2's
supported rates: 8000, 11025, 16000, 22050, 24000, 32000, 44100, 48000, 88200,
or 96000 Hz. The client reads it in 8 KiB chunks; the whole song never enters
the Go heap. Offline playlists can also name local files directly; see
`config.example.json`. The demo tones are explicitly local runtime tests.

Click a playlist, click a song, then click Play (or press Enter/Space).
Play toggles pause/resume for the current selected track. Previous/Next select
and play adjacent tracks on the loaded page; use the page buttons for more.
The player shows elapsed / total song time above the progress bar.
Stop releases audio. Tab switches keyboard focus between playlists and songs;
Up/Down select, Left/Right or PageUp/PageDown page, R refreshes, P/N skip,
S stops, G explicitly runs the Go garbage collector, and Esc closes the window.
Button labels show their shortcuts. Volume uses -/+ (or = without Shift), in
10% steps from 0% to 100%; M toggles mute while preserving the selected level.
Volume applies to Spotify streams, local Vorbis/WAV files and tones using integer PCM attenuation.
Already queued audio can take about a quarter-second to reflect a change.

The bottom panel shows Go heap allocation, live goroutine count from r2 stack
counters (TinyGo’s `runtime.NumGoroutine` is a constant stub), and the larger
of the UI loop’s stack high-water usage and finished goroutine peaks.
The build uses 64 KiB goroutine stacks for JSON, TLS and collector headroom. A network worker and an audio worker communicate with the UI
loop through buffered channels; networking never operates on a shared stack
from multiple goroutines. Three application loops stay responsive while the
TLS handshake or a filesystem operation yields. r2 has one PCM output stream:
opening another audio application takes it over.

## Limits and validation

The host protocol is versioned, pointer-free, size-asserted in Go and C++, and
uses atomic control words with two leased snapshot buffers. Closing the window
asks the child to exit. A child with no host heartbeat exits after ten seconds;
the host never frees a block while a live child may still be using it.

Config and HTTP bodies are limited to 64 KiB. Live API lists are paged rather
than loading a whole library. The status line reports authentication, permission,
rate-limit, TLS and audio failures without exposing tokens.

Host unit tests cover token refresh/rotation, bounded authentication retries,
paging, API item formats, unavailable tracks, WAV chunk validation, bounded HTTP
framing and shared ABI offsets. TinyGo and Memento builds check the target-side
integration. An isolated QEMU run verified desktop launch, tone and local WAV output through
HD Audio, pause/resume, previous/next, stop, explicit garbage collection during
playback, and clean close/reopen. Captured PCM contained nonzero stereo samples;
the task list contained no crashed clients after shutdown. The window reported
three live Go goroutines and an 8056-byte UI stack high-water mark after collection.
The user has verified live playlist refresh on bare metal. A live Premium account check
authenticated through AP/login5, downloaded encrypted audio and decoded 441,920
stereo frames at 44,100 Hz with nonzero PCM across multiple CDN ranges. An isolated QEMU run with a Westmere CPU model verified the linked integer
Vorbis decoder through r2 HD Audio. Its captured stereo PCM measured the
expected 330 Hz fixture, and GC, volume/mute and close/reopen remained usable.
The user has also reported initial account playback on bare metal; longer playback
with the TCP fixes below still needs target verification. Decoder tests include actual Vorbis PCM and
an encrypted HTTP range → AES-CTR → Vorbis pipeline. OAuth tests cover pending
pairing, polling slowdown, cancellation, refresh rotation and read-only configs.

Streaming prefers Vorbis 96 kbps, with 160/320 kbps as fallbacks. Client-token
challenges other than a direct grant, unsupported login5 challenges, and tracks
without a supported Vorbis file currently report errors. Seeking, automatic
cross-page track advancement and Spotify Connect discovery are not implemented.
Stopping or selecting another song cancels the current generation; compressed
input uses 4 KiB ranges for the first 16 KiB, then 16 KiB ranges over a reused
HTTPS connection. Vorbis headers are fed to the decoder incrementally in 4 KiB
blocks. Failed CDN downloads retry at most three times, rotating among the URLs
Spotify supplied for the same audio file. Stop cancels retries. CDN requests have a
30-second idle timeout, renewed when encrypted data moves. DNS, TCP connection
setup and the TLS handshake have separate deadlines; the initial handshake gets
at least 60 seconds for older CPUs. Stop/close/track changes cancel blocked TCP
waits. Each AP audio-key request gets a fresh deadline after preceding HTTPS
requests. Decoder
production follows buffer availability and coalesces short Vorbis blocks; it is
not paced at one block per timer tick. Ten reusable PCM buffers cross a bounded channel
by pointer; each buffer has one owner until the audio worker returns it to the pool.
Native regression checks passed in QEMU for TCP receive-window reopening,
window-update retries, overlapping retransmissions, reordered receive bursts,
Go scheduling during a blocked read, cancellation, a large Vorbis codebook on a
Go task, and writing, rotating and reopening a key in `/mnt/tmp`.

Audio resolution supports both legacy track file lists and the separate
`AUDIO_FILES` extended-metadata response used by current Spotify clients.
Missing or malformed metadata is reported separately from unsupported codecs.
Playback status and errors identify metadata, audio-key, storage, CDN download,
or login failures. Regression tests resolve modern metadata through an actual
encrypted AP audio-key exchange with an expired prior deadline.

Large Vorbis codebooks use heap scratch instead of variable-sized stack tables.
A 16,384-entry codebook reproduced a crash with the original 64 KiB stack;
the heap version passes that stack limit and allocation-failure cleanup tests.
The TCP receiver retains a bounded window of reordered segments and repeats
receive-window updates, reducing stalls after lost or reordered packets. Timeout
messages include received-byte and gap counts for target diagnosis.

For a development-only live protocol check (decoding without host playback):

```sh
make -C ../r2tls
make -C codec
CCACHE_DISABLE=1 go run -tags=r2cryptotest ./tools/streamcheck --config /path/to/private/config.json
```

This diagnostic is not shipped or required at runtime. It may ask you to pair
and persists refresh token rotation to the supplied file. See
[THIRD_PARTY.md](THIRD_PARTY.md) for decoder and cipher provenance.

Spotify references: [PKCE sign-in](https://developer.spotify.com/documentation/web-api/tutorials/code-pkce-flow),
[current-user playlists](https://developer.spotify.com/documentation/web-api/reference/get-a-list-of-current-users-playlists),
[playlist items](https://developer.spotify.com/documentation/web-api/reference/get-playlists-items).

Native networking regression variant (for development only): compile with
`-tags=r2netcheck`. At startup it checks TCP zero-window reopening, overlapping
retransmissions, another Go task running during a quiet TCP read, cancellation,
and a `/mnt/tmp/STEST.KEY` write/rotate/reopen. The normal build omits these checks.

## Crash diagnostics

The client writes its latest streaming stage and memory figures to
`/mnt/tmp/SPOTIFY.LOG`. Runtime panic output is appended using fixed buffers,
so an exhausted Go heap can still be reported. Memento displays the panic text,
task fault address, or heartbeat exit reason. The log contains no account tokens
and lasts until reboot; read it before restarting the application, which replaces it.

This diagnostics update requires both the rebuilt `spotify.elf` and
`memento.elf` (host ABI version 4). Rebuild the TinyGo image after runtime changes:
`make -C ../tinygo-r2 image`, then rebuild the application and Memento.

Decoder tests include 100 alternating finish/abort/reopen cycles and verify that
native allocations return to their baseline. The optional `r2netcheck` build
runs these cycles inside r2 using `/mnt/tar/opt/music/stress.ogg` (copy
`codec/testdata/tone.ogg` there), alongside TCP and credential-cache checks.
The separate `r2faultcheck` build intentionally panics to test crash reporting;
never install it as the normal client.
